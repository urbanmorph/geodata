Quick start

Find the district for a point, then list the blocks in it.

curl

# 1. Which district is this point in?
curl "https://bharatlas.com/api/v1/locate?lat=12.9716&lng=77.5946&layers=lgd_districts" \
  -H "User-Agent: my-app/1.0 (+https://example.org)"

# 2. Every block in that district (dist_lgd 525)
curl "https://bharatlas.com/api/v1/layers/lgd_blocks/query?where=dist_lgd=525&select=block_name,block_lgd"

JavaScript

const base = "https://bharatlas.com/api/v1";
const here = await fetch(`${base}/locate?lat=12.9716&lng=77.5946&layers=lgd_districts`).then((r) => r.json());
const { dist_lgd } = here.results.boundaries[0].feature.properties;   // 525
const blocks = await fetch(`${base}/layers/lgd_blocks/query?where=dist_lgd=${dist_lgd}`).then((r) => r.json());

Python, a whole layer locally

import duckdb, requests
layer = requests.get("https://bharatlas.com/api/v1/layers/lgd_blocks").json()["data"]
url = layer["downloads"]["parquet"]["url"]          # all of India in one file
duckdb.sql(f"SELECT block_name, block_lgd FROM '{url}' WHERE dist_lgd = 525").show()

An AI assistant

Codes to join on

Names change and are spelled many ways; codes don’t. Join your data to ours on the Local Government Directory (LGD) codes. The LGD layers also carry the Census 2011 codes, so older data joins too.

LevelLayerLGD code columnExample
Statelgd_statesState_LGD29, Karnataka
Districtlgd_districtsdist_lgd525, Bengaluru Urban (Census 2011 dtcode11: 572)
Sub-districtlgd_subdistrictssubdt_lgd5542, Bengaluru North
Blocklgd_blocksblock_lgd5761, Bengaluru North
Villagelgd_villagesvil_lgd612833, Suradenpura
City wardwards_bengaluru_bbmp_2022LGD_WardCode1302853, Shantala Nagar

Constituencies carry the Election Commission’s ids: pc_id in lgd_parliament (2925, Bangalore Central) and AC_ID in lgd_assembly (29162, Shivajinagar).

We pass codes through exactly as the source publishes them and never renumber them.

coming Crosswalks: tables from Census 2011 codes and older district names to current LGD codes, so data from before a district was split still joins.

Limits and promises

WhatLimit
Read endpoints120 requests a minute per IP
/locate and /layers/:id/locate60 requests a minute per IP
Submissions (write)5 an hour, 20 a day per IP

Over a limit you get 429 with a retry-after header. Cloudflare DDoS protection applies to all endpoints. Need a million points? Download the layer and join locally, or get in touch.

Is it up?

The website, the API and collect are checked every 5 minutes from outside. status.bharatlas.com shows each one now, its uptime over 90 days and past outages, also as JSON.

Tell us who you are

Send a User-Agent naming your app and a link, such as User-Agent: ward-finder/2.1 (+https://example.org). It costs nothing, and it lets us warn you before a change and list you below.

What stays the same

/api/v1 only grows: new fields may appear, but existing fields are never renamed or removed. A breaking change ships as /v2, announced here, and /v1 keeps working for at least 6 months after that. Every response carries an x-api-version: v1 header.

Licences and credit

We don’t relicense anything. Each layer keeps the licence its source published it under, and /layers/:id says which, with who to credit. Credit the source when you use a layer; a link to bharatlas is welcome too.

API reference

Every endpoint and parameter. Base URL: https://bharatlas.com/api/v1. The same in machine-readable form: /api/v1/openapi.json.

Layers

GET /api/v1/layers

List all curated layers with pagination and filters.

ParamTypeDescription
categorystringFilter by category (e.g. boundaries, city-wards, environment)
levelstringFilter by admin level (e.g. state, district)
sourcestringFilter by data source (e.g. LGD, OpenCity)
qstringText search across id, source, notes
limitintResults per page (default 100, max 500)
offsetintSkip N results (default 0)
curl https://bharatlas.com/api/v1/layers?category=city-wards&limit=5

GET /api/v1/layers/:id

Single layer detail with download URLs, licence and attribution.

curl https://bharatlas.com/api/v1/layers/lgd_states

GET /api/v1/layers/:id/schema

Column names, types, and sample values. Reads parquet metadata from R2 at runtime. Use this to discover what columns a layer has before querying. Nested columns (structs, lists, maps, such as Overture's names or addresses) are listed with type nested: you can select them, but not filter or group on them.

curl https://bharatlas.com/api/v1/layers/airports/schema

GET /api/v1/layers/:id/query

Query layer data with filters and grouping. Reads the parquet from R2 at runtime, no pre-computation needed. Works for curated and community layers.

ParamTypeDescription
selectstringComma-separated column names to return
wherestringExact, case-insensitive match on flat columns: col1=val1,col2=val2. Or pass columns directly as params: ?state=KA&type=INTERNATIONAL (use this form when a value contains a comma). A nested column returns 400 with the list of flat columns.
group_bystringGroup by column, returns value counts
sumstringWith group_by: comma-separated numeric columns to total per group, returned as sums. Percentages are not additive, so sum the amounts and recompute shares.
limitintMax rows (default 100, max 1000)
include_centroidboolAdds _lat/_lng (bounding-box centre) to each row where the layer has bounding-box columns. Default true; pass false to leave them out.
# Airports in Bangalore district (the layer's own spelling; a miss returns hints with the values)
curl "https://bharatlas.com/api/v1/layers/airports/query?where=district=Bangalore&select=name,type"

# Forests by type, across India
curl "https://bharatlas.com/api/v1/layers/soi_forests/query?group_by=type"

# National parks vs wildlife sanctuaries
curl "https://bharatlas.com/api/v1/layers/gs_wildlife/query?group_by=category"

# Installed power capacity (MW) by plant type
curl "https://bharatlas.com/api/v1/layers/vedas_power_plants/query?group_by=layer&sum=inst_cap"

# Which blocks are in Bengaluru Urban (district LGD code 525)?
curl "https://bharatlas.com/api/v1/layers/lgd_blocks/query?where=dist_lgd=525&select=block_name,block_lgd"

Columns with geometry data (geom, wkb_geometry) are excluded from results. Rows are read row group by row group, so memory stays small on any layer; time grows with layer size. Most layers answer in about a second; on the largest (Overture places, 4.4M rows) a filter or group_by over the whole table takes several seconds, so filter on low-cardinality columns where you can.

Spatial

GET /api/v1/locate

Given a lat/lng, returns all polygon layers that contain that point: state, district, ward, pincode, forest, eco-zone, seismic zone, and more, each with its codes. The "where am I?" endpoint.

ParamTypeDescription
latfloat *Latitude (6 to 38, India bounding box)
lngfloat *Longitude (68 to 98, India bounding box)
layersstringComma-separated layer IDs, used as given (default: 13 admin and zone layers, plus the city ward layer covering the point)
zoomintTile resolution 4-16 (default 14, auto-capped to layer max zoom)
curl "https://bharatlas.com/api/v1/locate?lat=12.97&lng=77.59"

Response groups results by category:

{
  "point": { "lat": 12.97, "lng": 77.59 },
  "results": {
    "boundaries": [{
      "layer_id": "lgd_states",
      "level": "state",
      "feature": {
        "properties": { "STNAME": "KARNATAKA", "State_LGD": 29 }
      }
    }, {
      "layer_id": "lgd_districts",
      "level": "district",
      "feature": {
        "properties": { "dtname": "Bengaluru Urban", "dist_lgd": 525, "dtcode11": "572" }
      }
    }]
  },
  "queried_layers": ["lgd_states", "lgd_districts", ...],
  "timing_ms": 450
}

GET /api/v1/nearby

Find features from any layer near a point, nearest first. Works for points, polygons, and lines: features are ranked by Haversine distance to their bounding-box centres.

ParamTypeDescription
latfloat *Center latitude (6-38)
lngfloat *Center longitude (68-98)
layerstring *Layer ID to search
radius_kmfloatSearch radius in km (default 25, max 200)
limitintMax results (default 20, max 100)
# Reservoirs within 50km of Bengaluru
curl "https://bharatlas.com/api/v1/nearby?lat=12.97&lng=77.59&layer=wris_reservoirs&radius_km=50"

# Wildlife sanctuaries within 100km of Mysuru
curl "https://bharatlas.com/api/v1/nearby?lat=12.30&lng=76.65&layer=gs_wildlife&radius_km=100"

Admin units by code

For a point, use /locate. To find a unit by its LGD code, or list the units under one, query the LGD layers, e.g. /layers/lgd_districts/query?where=dist_lgd=525 (Bengaluru Urban) or /layers/lgd_blocks/query?where=dist_lgd=525 (its blocks).

Counts and Stats

GET /api/v1/layers/:id/counts

Feature counts with optional column grouping. Without group_by, returns the total and lists all groupable columns. With group_by, returns value-level counts for that column.

ParamTypeDescription
group_bystringColumn name to group by (one listed in groupable_columns, e.g. zone)
# Total and groupable columns
curl https://bharatlas.com/api/v1/layers/wards_pcmc/counts

# Count wards per zone in PCMC
curl https://bharatlas.com/api/v1/layers/wards_pcmc/counts?group_by=zone

Counts come from pre-computed statistics: columns with fewer than 200 distinct values can be grouped, one column at a time. A layer without statistics returns its total only; use /query with group_by for any column of any layer.

Response Format

All endpoints return JSON. List endpoints wrap results in:

{ "data": [...], "total": N, "limit": 100, "offset": 0 }

Detail endpoints wrap in:

{ "data": { ... } }

Errors return:

{ "error": "Not found", "status": 404 }

collect API (write) stable

collect is the write side: design a map form, collect points from contributors, and publish approved points into this catalog. It runs as a separate service with its own origin and auth, so it has its own section here rather than sitting under /api/v1 above.

Base URL: https://collect.bharatlas.com/api/collect/v1

Auth is a bearer token in the URL fragment of each share link (kept out of server logs); the field-definition contract is the public meta-schema at https://collect.bharatlas.com/schema/v1.json. Creating a map programmatically needs an API key (the anti-abuse gate) via the X-API-Key header, since there is no browser Turnstile.

MethodEndpointWhat
POST/collectionscreate a map (X-API-Key, or Turnstile in the browser); returns admin / collect / view links
GET/collections/:idmap metadata + counts
PATCH/collections/:idedit settings (admin)
POST/collections/:id/recordsadd one point (contributor)
GET/collections/:id/recordsrecords as GeoJSON, scoped by token
POST/collections/:id/importbulk import with a source + rights attestation (admin)
POST/records/:id/moderateapprove / reject one point (admin)
POST/collections/:id/publishsubmit approved points to the catalog for review (admin)
# 1. Create a map (needs an API key; body follows the meta-schema)
curl -X POST https://collect.bharatlas.com/api/collect/v1/collections \
  -H "X-API-Key: cak_..." -H "content-type: application/json" \
  -d '{ ...map definition per /schema/v1.json... }'
# returns admin / collect / view links; each link's token lives in its URL fragment

# 2. Review incoming points (admin token from the returned admin link)
curl https://collect.bharatlas.com/api/collect/v1/collections/ID/records \
  -H "authorization: Bearer adm_..."

# 3. Submit approved points to the catalog for review (admin token)
#    a maintainer approves the submission before it appears in the catalog
curl -X POST https://collect.bharatlas.com/api/collect/v1/collections/ID/publish \
  -H "authorization: Bearer adm_..."

Field contributors add points from the browser via the shared collect link (Turnstile-gated), so that step is a tap, not a curl. Or drive the whole flow from an LLM: the bharatlas MCP (npx bharatlas-mcp@latest) authors collect maps too. Register a share link with register_map and its token scope (view / collect / admin) sets what you can do.
