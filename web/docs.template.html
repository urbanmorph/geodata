Quick start

Find the district for a point, then list the blocks in it.

curl

# 1. Which district is this point in?
curl "https://bharatlas.com/api/v1/locate?lat=12.9716&lng=77.5946&layers=lgd_districts" \
  -H "User-Agent: my-app/1.0"

# 2. Every block in that district (dist_lgd 525)
curl "https://bharatlas.com/api/v1/layers/lgd_blocks/query?where=dist_lgd=525&select=block_name,block_lgd"

JavaScript

const base = "https://bharatlas.com/api/v1";
const here = await fetch(`${base}/locate?lat=12.9716&lng=77.5946&layers=lgd_districts`).then((r) => r.json());
const { dist_lgd } = here.results.boundaries[0].feature.properties;   // 525
const blocks = await fetch(`${base}/layers/lgd_blocks/query?where=dist_lgd=${dist_lgd}`).then((r) => r.json());

Python, a whole layer locally

import duckdb, requests
layer = requests.get("https://bharatlas.com/api/v1/layers/lgd_blocks").json()["data"]
url = layer["downloads"]["parquet"]["url"]          # all of India in one file
duckdb.sql(f"SELECT block_name, block_lgd FROM '{url}' WHERE dist_lgd = 525").show()

An AI assistant

# Claude Code, hosted server (read-only, no install)
claude mcp add --transport http bharatlas https://bharatlas.com/mcp

# then ask: "Which district and ward is 12.9716, 77.5946 in, and which blocks share that district?"

Codes to join on

Names change and are spelled many ways; codes don’t. Join your data to ours on the Local Government Directory (LGD) codes. The LGD layers also carry the Census 2011 codes, so older data joins too.

LevelLayerLGD code columnExample
Statelgd_statesState_LGD29, Karnataka
Districtlgd_districtsdist_lgd525, Bengaluru Urban (Census 2011 dtcode11: 572)
Sub-districtlgd_subdistrictssubdt_lgd5542, Bengaluru North
Blocklgd_blocksblock_lgd5761, Bengaluru North
Villagelgd_villagesvil_lgd612833, Suradenpura
City wardwards_bengaluru_bbmp_2022LGD_WardCode1302853, Shantala Nagar

Constituencies carry the Election Commission’s ids: pc_id in lgd_parliament (2925, Bangalore Central) and AC_ID in lgd_assembly (29162, Shivajinagar).

We pass codes through exactly as the source publishes them and never renumber them.

Crosswalks: the Census 2011 to LGD crosswalk links each Census 2011 code to the current LGD codes at every level (state, district, sub-district, block, village) and says how it changed (1:1, split, merge), so data from before a unit was split still joins. It is a dated release, as CSV and Parquet.

Over a limit you get 429 with a retry-after header. Cloudflare DDoS protection applies to all endpoints. Need a million points? Download the layer and join locally, or get in touch.

Is it up?

The website, the API and collect are checked every 5 minutes from outside. status.bharatlas.com shows each one now, its uptime over 90 days and past outages, also as JSON.

Name your app

Please send a User-Agent that names your app (for example my-app/1.0). We read it only to tell apps, AI tools and crawlers apart, so our counts of how each mode is used stay honest. We don't store it, and we don't track who you are.

What stays the same

/api/v1 only grows: new fields may appear, but existing fields are never renamed or removed. A breaking change ships as /v2, announced here, and /v1 keeps working for at least 6 months after that. Every response carries an x-api-version: v1 header.

Licences and credit

We don’t relicense anything. Each layer keeps the licence its source published it under, and /layers/:id says which, with who to credit. Credit the source when you use a layer; a link to bharatlas is welcome too.

API reference

Every endpoint and parameter. Base URL: https://bharatlas.com/api/v1. The same in machine-readable form: /api/v1/openapi.json.

Layers

GET /api/v1/layers

List all curated layers with pagination and filters.

ParamTypeDescription
categorystringFilter by category (e.g. boundaries, city-wards, environment)
levelstringFilter by admin level (e.g. state, district)
sourcestringFilter by data source (e.g. LGD, OpenCity)
qstringText search (case-insensitive substring) across id, source, notes, category, level and tags
limitintResults per page (default 100, max 500)
offsetintSkip N results (default 0)
curl https://bharatlas.com/api/v1/layers?category=city-wards&limit=5

GET /api/v1/layers/:id

Single layer detail with download URLs, licence and attribution.

curl https://bharatlas.com/api/v1/layers/lgd_states

GET /api/v1/layers/:id/schema

Column names, types, and sample values. Reads parquet metadata from R2 at runtime. Use this to discover what columns a layer has before querying. Nested columns (structs, lists, maps, such as Overture's names or addresses) are listed with type nested: you can select them, but not filter or group on them.

curl https://bharatlas.com/api/v1/layers/airports/schema

GET /api/v1/layers/:id/query

Query layer data with filters and grouping. Reads the parquet from R2 at runtime, no pre-computation needed. Works for curated and community layers. An unknown column in select, where, filter, group_by or sum is a 400 that lists the layer’s columns, before any row is read. A filter that matches nothing returns hints with the column’s values. Answers are kept in the edge cache for up to an hour.

ParamTypeDescription
selectstringComma-separated column names to return
wherestringExact, case-insensitive match on flat columns: col1=val1,col2=val2. Or pass columns directly as params: ?state=KA&type=INTERNATIONAL (use this form when a value contains a comma). A nested column returns 400 with the list of flat columns.
group_bystringGroup by column, returns value counts
sumstringWith group_by: comma-separated numeric columns to total per group, returned as sums. Percentages are not additive, so sum the amounts and recompute shares.
limitintMax rows (default 100, max 1000)
include_centroidboolAdds _lat/_lng (bounding-box centre) to each row where the layer has bounding-box columns. Default true; pass false to leave them out.
filterJSONFilters as a JSON list, for more than exact matches: [{"col":"sname","kind":"in","values":["KA","TN"]}]. Kinds: in (any of the values, case-insensitive), range (numeric min and/or max), search (case-insensitive substring q), bool (v). Combined with where: all must match.
order_bystringReserved, not applied yet: rows come in file order. Accepted so it is never read as a column filter.
format, estimatestringNot used by /query (they belong to /layers/:id/export). Accepted so they are never read as column filters.
# Airports in Bengaluru Urban district (the layer's own spelling; a miss returns hints with the values)
curl "https://bharatlas.com/api/v1/layers/airports/query?where=district=Bengaluru%20Urban&select=name,type"

# Forests by type, across India
curl "https://bharatlas.com/api/v1/layers/soi_forests/query?group_by=type"

# National parks vs wildlife sanctuaries
curl "https://bharatlas.com/api/v1/layers/gs_wildlife/query?group_by=category"

# Installed power capacity (MW) by plant type
curl "https://bharatlas.com/api/v1/layers/vedas_power_plants/query?group_by=layer&sum=inst_cap"

# Which blocks are in Bengaluru Urban (district LGD code 525)?
curl "https://bharatlas.com/api/v1/layers/lgd_blocks/query?where=dist_lgd=525&select=block_name,block_lgd"
# Hospitals in Karnataka or Kerala, counted per state (a filter for more than exact matches)
curl -G "https://bharatlas.com/api/v1/layers/nhp_hospitals/query" \
  --data-urlencode 'filter=[{"col":"State","kind":"in","values":["Karnataka","Kerala"]}]' \
  --data-urlencode 'group_by=State'

Columns with geometry data (geom, wkb_geometry) are excluded from results. Rows are read row group by row group, so memory stays small on any layer; time grows with layer size. Most layers answer in about a second; on the largest (Overture places, 4.8M rows) a filter or group_by over the whole table takes several seconds, so filter on low-cardinality columns where you can.

GET /api/v1/layers/:id/export

Every row matching a filter, with all its columns and its shape, as a file. Takes where and filter in the same forms as /query; a filter is required, since the whole layer is a download. At most 50,000 rows and an estimated 100 MB: above either the answer is 400 with the match count and the estimate, so narrow the filter or use the layer’s downloads. GeoJSON and KML also refuse matches spread over more than 1 GB of the layer’s shapes; CSV has no such limit and carries the bounding-box centre as _lat, _lng instead of the shape. An export that fails after it starts ends the connection without completing, so you see a failed download, never a short file.

ParamTypeDescription
formatstringgeojson (default), kml or csv
estimatestring1: only the match count and each format’s estimated size, as JSON, without exporting
wherestringExact, case-insensitive matches: col1=val1,col2=val2
filterJSONAs in /query: in, range, search and bool filters
# How big would it be?
curl "https://bharatlas.com/api/v1/layers/lgd_villages/export?where=dist_lgd=525&estimate=1"

# Bengaluru Urban's villages as GeoJSON
curl -o villages.geojson "https://bharatlas.com/api/v1/layers/lgd_villages/export?where=dist_lgd=525&format=geojson"

Spatial

GET /api/v1/locate

Given a lat/lng, returns all polygon layers that contain that point: state, district, ward, pincode, forest, eco-zone, seismic zone, and more, each with its codes. The "where am I?" endpoint.

ParamTypeDescription
latfloat *Latitude (6 to 38, India bounding box)
lngfloat *Longitude (68 to 98, India bounding box)
layersstringComma-separated layer IDs to test, at most 25 (default: admin and zone layers, plus the city ward layer covering the point). A retired id is tested as its successor; an id that is not a layer comes back in unknown_layers, and when none is a layer the answer is 400.
zoomintTile resolution 4-16 (default 14, auto-capped to layer max zoom)
curl "https://bharatlas.com/api/v1/locate?lat=12.97&lng=77.59"

Response groups results by category:

{
  "point": { "lat": 12.97, "lng": 77.59 },
  "results": {
    "boundaries": [{
      "layer_id": "lgd_states",
      "level": "state",
      "feature": {
        "properties": { "STNAME": "KARNATAKA", "State_LGD": 29 }
      }
    }, {
      "layer_id": "lgd_districts",
      "level": "district",
      "feature": {
        "properties": { "dtname": "Bengaluru Urban", "dist_lgd": 525, "dtcode11": "572" }
      }
    }]
  },
  "queried_layers": ["lgd_states", "lgd_districts", ...],
  "timing_ms": 450
}

GET /api/v1/layers/:id/locate

The feature of one layer that contains a point, or the nearest one: “which ward is this?”, or “the nearest airport”. Never cached.

ParamTypeDescription
latfloat *Latitude (6 to 38)
lngfloat *Longitude (68 to 98)
modestringauto (default: contains, then nearest), contains (point-in-polygon) or nearest (the closest feature, with distance_km and a compass bearing)
zoomintTile zoom for contains, 4 to 16 (default 14)
radius_kmfloatSearch radius for nearest, 1 to 200 (default 25)

When nothing contains the point and nothing is within the radius, feature is null with out_of_coverage: true.

# Which Bengaluru ward is this point in?
curl "https://bharatlas.com/api/v1/layers/wards_bengaluru_gba/locate?lat=12.9716&lng=77.5946"

# The nearest airport to a point
curl "https://bharatlas.com/api/v1/layers/airports/locate?lat=12.97&lng=77.59&mode=nearest&radius_km=100"

GET /api/v1/nearby

Find features from any layer near a point, nearest first. Works for points, polygons, and lines: features are ranked by Haversine distance to their bounding-box centres.

ParamTypeDescription
latfloat *Center latitude (6-38)
lngfloat *Center longitude (68-98)
layerstring *Layer ID to search
radius_kmfloatSearch radius in km (default 25, max 200)
limitintMax results (default 20, max 100)
# Reservoirs within 50km of Bengaluru
curl "https://bharatlas.com/api/v1/nearby?lat=12.97&lng=77.59&layer=wris_reservoirs&radius_km=50"

# Wildlife sanctuaries within 100km of Mysuru
curl "https://bharatlas.com/api/v1/nearby?lat=12.30&lng=76.65&layer=gs_wildlife&radius_km=100"

GET /api/v1/ground

What is below a point, in one call instead of a dozen locate and nearby calls. The answer has a one-line summary and sections:

  • seismic: seismic zone, active faults within 50 km, GSI lineaments within 25 km and NRSC lineaments within 10 km (non-commercial), each by true distance to the line, recorded earthquakes within 50 km
  • geology: rock type (GSI 1:50,000 lithology, and the 1:2 million map as a coarse fallback), landform (NRSC geomorphology, non-commercial), GSI exploration boreholes within 25 km
  • resources: coal and hydrocarbon blocks (0 km when inside), critical minerals, mineral deposits, hot springs and oil or gas wells nearby
  • groundwater: aquifer and stage of groundwater extraction (CGWB), groundwater prospects (NRSC, non-commercial), wells counted by the 2017-18 Minor Irrigation Census, the nearest groundwater quality samples (non-commercial), near-surface permeability and porosity (GLHYMPS 2.0, decoded to m2 and m/s), Atal Bhujal wells within 10 km with their latest pre- and post-monsoon water levels, and India-WRIS monitoring stations within 10 km (last depth, pre- and post-monsoon depth and year, 2015-2024 trend; links.readings is the full readings download)
  • soil: clay, sand, silt, pH, organic carbon, bulk density, CEC and nitrogen at 0-5, 5-15 and 15-30 cm, and the WRB soil group, from ISRIC SoilGrids 2.0 (250 m, Poggio et al. 2021, CC BY 4.0); the nearest Soil Health Card sample within 5 km
  • subsidence: in the megacities it covers, the median vertical land motion (cm/yr, negative is sinking) of satellite points within 500 m
  • underground: tunnels and buried pipelines or cables within 1 km, mine shafts, adits and caves within 5 km (OpenStreetMap)
  • watershed: in rural areas, the CoRE Stack micro-watershed water balance and drought record; whether NDEM mapped the point as flooded between 1998 and 2022 (non-commercial)

Each entry names its layer_id and carries its credit (source and licence); a non-commercial layer says so with non_commercial and licence_notice. Units are in field names (clay_pct, distance_km) or in units. contains entries list the features holding the point; nearest entries give the count within radius_km and the nearest few. Each entry's status is found, none_within_radius (the layer covers the area, nothing is that close) or not_covered (the layer does not reach the point: subsidence is mapped for some cities only, Atal Bhujal wells for seven states, CoRE Stack for some rural tehsils). SoilGrids leaves out water and built-up land: there depths is null with a reason. A layer that could not be read in time is listed in unavailable and the rest still answer. Shares the locate limit (60 a minute).

ParamTypeDescription
latfloat *Latitude (6-38)
lngfloat *Longitude (68-98)
open_onlybooltrue leaves out the non-commercial layers (listed in omitted_non_commercial)

Every entry says its about: scale or resolution, the period its data describe and the date we fetched it. This is screening information, not a site investigation: the answer's disclaimer says so. The answer is for the point snapped to about 100 m.

# What is under this plot in south-west Delhi?
curl "https://bharatlas.com/api/v1/ground?lat=28.525&lng=77.085"

GET /api/v1/surface

What is on the ground at a point, in one call. Same conventions as /ground (credit, licence, about, status, open_only, summary, disclaimer); its sections:

  • place: state, district, sub-district, block, constituencies, pincode, and the city ward (or the national ward map elsewhere)
  • land: land cover (ESA WorldCover 2021, resampled to 30 m), elevation and slope (Copernicus DEM GLO-90, about 90 m), people per km2 (WorldPop 2020, about 100 m), CoRE Stack block land use (2023-24), land degradation (NRSC, non-commercial)
  • climate: agro-climatic, agro-ecological, eco and biogeographic zones
  • water: basin and sub-basin; the nearest river, water body, reservoir, dam, wetland and Ramsar site, each by true distance to its line or outline; Amrit Sarovar ponds; recorded floods and NDEM flood extents (non-commercial)
  • hazards: seismic zone, landslide hazard (non-commercial) and recorded landslides within 5 km, cyclone tracks within 100 km (non-commercial), coastal regulation zone
  • protected: recorded forest, and the nearest protected area and wildlife corridor (0 km when inside)
  • access: nearest national highway, railway station, metro or suburban station, airport and bus stop (bus stops exist only for some cities: elsewhere not_covered)
  • services: nearest hospital or health facility from three sources (each named), nearest school, and the count of mapped places within 1 km
  • infrastructure: nearest power line, power plant and water-supply facility, and the distance to India's outline (the coast, or a land border where that is nearer)

Raster entries carry values (field names carry units). For the air above the point, air points to the mugilu MCP server's conditions_at with the same coordinates.

ParamTypeDescription
latfloat *Latitude (6-38)
lngfloat *Longitude (68-98)
open_onlybooltrue leaves out the non-commercial layers
# What is around this point in central Kolkata?
curl "https://bharatlas.com/api/v1/surface?lat=22.57&lng=88.36"

For a point, use /locate. To find a unit by its LGD code, or list the units under one, query the LGD layers, e.g. /layers/lgd_districts/query?where=dist_lgd=525 (Bengaluru Urban) or /layers/lgd_blocks/query?where=dist_lgd=525 (its blocks).

Counts and Stats

GET /api/v1/layers/:id/counts

Deprecated, kept for existing callers: /layers/:id/query?group_by=<col> gives the same counts, with where, filter and sum. Without group_by, returns the total and lists the groupable columns; with filter_col and filter_val, the total of matching rows. With group_by, returns value-level counts for that column.

ParamTypeDescription

Releases

GET /api/v1/releases

Dated releases, newest first. A release code is bharatlas-<dataset>-<year>.<month> (e.g. bharatlas-cw-2026.11); it is never reused and its files never change. collect API (write) stable

collect is the write side: design a map form, collect points from contributors, and submit approved points to bharatlas as a layer (reviewed before it appears). It runs as a separate service with its own origin and auth, so it has its own section here rather than sitting under /api/v1 above.

Base URL: https://collect.bharatlas.com/api/collect/v1

Auth is a bearer token in the URL fragment of each share link (kept out of server logs); the field-definition contract is the public meta-schema at https://collect.bharatlas.com/schema/v1.json. Creating a map programmatically needs an API key (the anti-abuse gate) via the X-API-Key header, since there is no browser Turnstile.

MethodEndpointWhat
POST/collectionscreate a map (X-API-Key, or Turnstile in the browser); returns admin / collect / view links
GET/collections/:idmap metadata + counts
PATCH/collections/:idedit settings (admin)
POST/collections/:id/recordsadd one point (contributor)
GET/collections/:id/recordsrecords as GeoJSON, scoped by token
POST/collections/:id/importbulk import with a source + rights attestation (admin)
POST/records/:id/moderateapprove / reject one point (admin)
POST/collections/:id/publishsubmit approved points to bharatlas for review (admin)
# 1. Create a map (needs an API key; body follows the meta-schema)
curl -X POST https://collect.bharatlas.com/api/collect/v1/collections \
  -H "X-API-Key: cak_..." -H "content-type: application/json" \
  -d '{ ...map definition per /schema/v1.json... }'
# returns admin / collect / view links; each link's token lives in its URL fragment

# 2. Review incoming points (admin token from the returned admin link)
curl https://collect.bharatlas.com/api/collect/v1/collections/ID/records \
  -H "authorization: Bearer adm_..."

# 3. Submit approved points to bharatlas for review (admin token)
#    a maintainer approves the submission before it appears on bharatlas

Field contributors add points from the browser via the shared collect link (Turnstile-gated), so that step is a tap, not a curl. Or drive the whole flow from an LLM: the bharatlas MCP (npx bharatlas-mcp@latest) authors collect maps too. Register a share link with register_map and its token scope (view / collect / admin) sets what you can do.

For LLMs

Use the bharatlas MCP server (npx bharatlas-mcp@latest) to connect Claude, GPT, Gemini, or any MCP-compatible LLM directly to this API. 17 tools with built-in instructions: 8 for reading (schema-first querying, spatial joins, multi-source awareness) plus 9 for authoring collect maps.
